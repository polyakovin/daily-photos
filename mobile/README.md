# «Фото дня» для iOS и Android

Мобильный MVP показывает фотографии из выбранной пользователем папки в календаре и на карте.
Приложение построено на Expo SDK 57, React Native 0.86 и TypeScript.

## Возможности первой версии

- выбор папки через системный интерфейс iOS или Android;
- рекурсивное чтение архива и явные пользовательские операции записи;
- режимы «Годы», «Год», «Месяц» и «Неделя» с переходами между масштабами;
- общая карта всех фотографий с геометками, группировкой совпадающих мест и открытием снимка;
  метки и тайлы остаются правильно выровненными при жестовом масштабировании и изменении размера
  области карты, а критические стили карты не зависят от загрузки внешнего CSS; как и на десктопе,
  близкие точки динамически объединяются по текущему масштабу, а в DOM остаются только видимые
  кластеры; в режиме «Карта» область карты занимает всю оставшуюся высоту экрана до нижней
  безопасной границы;
- календарь с неделей от понедельника, превью и количеством вариантов одного дня;
- горизонтальные свайпы между периодами календаря;
- кнопка «Сегодня» для возврата к текущей неделе, месяцу или году;
- навигация календаря ограничена периодом от первой фотографии до сегодняшней даты;
- месячный календарь равномерно растягивает шесть недель до нижней безопасной границы экрана;
- недельный режим показывает семь полноширинных горизонтальных полос, но всегда ограничивается
  доступной высотой экрана без вертикального переполнения;
- полноэкранный просмотр с горизонтальным листанием всей хронологии архива и отступами от
  статус-бара, выреза экрана и индикатора Home;
- фотография центрируется во всей безопасной области; кнопка закрытия находится справа сверху,
  а нижняя панель без счётчиков содержит функциональные действия, варианты дня и интерактивную дату
  с названием месяца, например `12 августа 2026г.`;
  на iOS 26 элементы используют системный Liquid Glass, на остальных
  платформах — полупрозрачный стеклянный fallback;
- временное увеличение фотографии жестом сведения-разведения пальцев до `4×` относительно точки
  между пальцами и панорамирование движением двух пальцев, без листания соседних снимков во время
  жеста и с плавным возвратом масштаба и позиции после отпускания;
- перелистывание фотографий только горизонтальными свайпами, без навигационных стрелок;
- масштабирование включается сразу при появлении второго пальца, без ожидания его движения; если
  в этот момент выполнялся свайп, он отменяется и не возобновляется до полного отпускания пальцев;
- просмотр Markdown-заметки в стеклянной накладке поверх фотографии и её редактирование там же;
  записи сохраняются в совместимой папке `_diary`;
- смена даты с переносом оригинала без перезаписи существующего файла;
- выбор фото дня, фото месяца и фото года;
- добавление и удаление геометки через карту или поиск места;
- полупрозрачная мини-карта в левом верхнем углу фотографии: маркер и координаты видны независимо
  от загрузки внешней библиотеки карты; сохранённая вручную геометка имеет приоритет, иначе
  координаты лениво читаются из GPS-блока EXIF, а для iCloud при необходимости повторно — из
  локальной копии оригинала; нажатие на мини-карту открывает интерактивную карту окрестностей с
  точкой фотографии по центру;
- кнопка режима презентации в шапке основного экрана: отмеченные снимки блюрятся в календаре,
  карточках периодов, карте и просмотрщике, а состояние режима сохраняется между запусками;
- настройка блюра фотографии для презентации и удаление оригинала с подтверждением;
- двухфазный первый обход: точный подсчёт объектов, затем настоящий прогресс `обработано / всего`
  и фоновое обновление календаря порциями;
- локальный индекс выбранной папки для быстрого повторного запуска;
- при повторном запуске локальный индекс открывается до обращения к iCloud, а проверка архива
  продолжается в фоне; если File Provider не отвечает при открытии, ожидание завершается с
  понятным сообщением и действиями «Повторить» и «Другая папка»;
- фоновый прогрев JPEG-превью 480 px для всего индекса с дисковым кэшем приложения, сохраняемым
  между запусками;
- приоритетная очередь превью: видимые и открытые снимки обгоняют фоновые задачи, после чего
  прогрев расходится по хронологии от уже готовых соседних фотографий;
- не более двух параллельных задач превью, причём фоновый прогрев занимает только один слот;
- зависшая загрузка из iCloud или другого File Provider освобождает очередь по тайм-ауту, поэтому
  один недоступный файл не блокирует остальные превью; просмотрщик после повторной попытки
  показывает понятную ошибку и кнопку «Повторить» вместо бесконечного индикатора;
- светлая и тёмная темы с цветами десктопного приложения, системным выбором по умолчанию и
  сохранением ручного переключения;
- единая с десктопным приложением иконка для iOS и Android;
- минималистичные панели команд: пиктограммы берутся из Material Community Icons, у широких
  действий рядом остаётся короткая подпись, а результат мобильных операций подтверждается кратким
  неблокирующим toast-сообщением;
- сохранение доступа к выбранной папке между запусками.

Дата извлекается из путей `ГГГГ-ММ-ДД` и `ГГГГ/ММ/ДД`, совместимых с десктопным индексатором.
Если путь не содержит дату, используется дата изменения файла. Общая карта читает переносимые
геометки из `photo_locations.json`, а просмотрщик лениво читает GPS из EXIF открытого снимка,
когда ручная геометка не задана. Отдельный таймлайн остаётся следующим этапом мобильной версии.

Первый обход большой папки iCloud может занять время: приложение сначала считает объекты без
имитации процентов, затем показывает точное `обработано / всего` и начинает наполнять календарь до
окончания обхода. Готовый индекс
сохраняется только в песочнице приложения. При следующих запусках календарь сразу открывается из него,
а актуальность папки проверяется в фоне. Если iCloud или другой File Provider не отвечает при
получении доступа, приложение прекращает бесконечное ожидание, оставляет доступным сохранённый
календарь и предлагает повторить попытку либо выбрать другую папку. После получения индекса iOS и Android создают уменьшенные
превью для всего архива и сохраняют их в дисковом кэше приложения между запусками. Сначала
обрабатываются фотографии текущего экрана и открытый снимок, затем очередь расширяется в обе стороны
по хронологии от уже готовых фотографий. Если пользователь переходит к другому периоду, его снимки
сразу получают повышенный приоритет. Прогрев выполняется, пока приложение активно, не зависит от
открытого режима календаря и не блокирует интерфейс; полноразмерный файл читается только при открытии
снимка. iOS может приостановить работу после сворачивания приложения и продолжит прогрев при
следующем запуске.

При открытии фотографии просмотрщик сразу показывает готовое превью, а оригинал копирует через
нативный файловый API в локальный кэш отображения. Для iCloud это также инициирует загрузку файла из
облака; после завершения локальный оригинал заменяет превью без чёрного промежуточного экрана.
Задачи превью и оригиналов ограничены по времени: зависшая операция не удерживает общую очередь,
а недоступную фотографию можно загрузить повторно прямо из просмотрщика.

## Доступ к iCloud Drive

На iOS приложение открывает `UIDocumentPickerViewController` для выбора каталога. Пользователь
может перейти в iCloud Drive, «На iPhone» или подключённый File Provider и выбрать одну папку.
Полученный URL имеет security scope; нативный модуль сохраняет bookmark, восстанавливает его при
следующем запуске и удерживает доступ только во время работы приложения. Чтение и разрешённые
пользователем изменения iCloud выполняются через `NSFileCoordinator`. Это даёт рекурсивный доступ
только к выбранной папке, не запрашивая доступ ко всему iCloud Drive. Если File Provider не выдаёт
доступ, причина показывается прямо на экране выбора папки.

На Android тот же контракт реализован через `ACTION_OPEN_DOCUMENT_TREE`. URI дерева сохраняется с
постоянным разрешением на чтение и запись, а файлы обрабатываются через `DocumentsContract`.
Разрешение можно отозвать в системных настройках.

Фотографии и заметки не отправляются в сеть. При открытии карты приложение запрашивает только её
графические тайлы у OpenStreetMap, а при явном поиске места введённая строка передаётся сервису
OpenStreetMap Nominatim; координаты можно указать на карте без текстового поиска.

## Структура

- `App.tsx` — состояния выбора папки, календарь и просмотрщик;
- `src/calendar.ts` — чистая логика дат, календарной сетки и группировки снимков;
- `src/map.ts` — проверка координат и переносимая группировка фототочек;
- `modules/photo-archive/ios/` — Swift picker и security-scoped bookmark;
- `modules/photo-archive/android/` — Kotlin Storage Access Framework;
- `test/` — тесты переносимой календарной логики.

Каталоги `ios/` и `android/` создаются командой Expo prebuild и исключены из Git. Все долговечные
нативные изменения должны находиться в локальном модуле или конфигурации `app.json`.

## Разработка

```sh
nvm use
npm ci
npm run check
npm run ios      # Xcode и установленная iOS-платформа
npm run android  # JDK 17 и Android SDK
```

`npm run ios` и `npm run android` создают development build с локальным нативным модулем. Expo Go
его не содержит и для проверки выбора папки не используется.
После изменения API нативного модуля одного Fast Refresh недостаточно: приложение нужно заново
собрать и установить на устройство. До пересборки просмотрщик сохранит превью вместо аварийного
экрана, но локальный оригинал появится только в новой нативной сборке.

Для `expo-modules-jsi` 57.0.4 команда `npm ci` автоматически применяет узкий workaround
совместимости с компилятором Xcode 26.2: неоднозначный Swift-вызов `abs` квалифицируется как
`Swift.abs`. Тот же скрипт отключает параллельную подпись CocoaPods framework в Expo CLI: на
некоторых Keychain-конфигурациях она оставляет Hermes и React framework без подписи, хотя Xcode
сообщает об успешной сборке. Скрипт ничего не меняет, если Expo уже содержит другую реализацию.
